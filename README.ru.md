# dsh-telegram-plus

Уведомления в Telegram для [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness),
которые выглядят как обычные сообщения Telegram — и на которые можно **ответить
прямо из чата**.

Модель отвечает в Markdown (`**жирный**`, `## заголовки`, блоки кода, таблицы).
Обычные телеграм-плагины отправляют этот текст как есть, и в телефоне видны
звёздочки и обратные кавычки. Этот плагин рендерит разметку в HTML-подмножество
Telegram и идёт дальше: вопрос агента или запрос подтверждения инструмента
приходит сообщением с кнопками, а ваш тап (или ответ текстом) становится
ответом для DSH.

```
✅ Turn complete
📁 my-project — Fix the CI pipeline
👤 почему сборка красная?
🤖 **Нашёл**: ключ кэша собирается через `pwd` …

        [ Yes ]  [ No ]                 ← ответ на вопрос агента
    [ ✅ Allow once ] [ ❌ Reject ]      ← подтверждение инструмента
```

## Возможности

- **Форматирование Telegram** — `<b>`, `<i>`, `<s>`, `<code>`, `<pre>`,
  `<blockquote>`, `<a href>`; всё динамическое экранируется.
- **Длинные сообщения не обрезаются**, а делятся по строкам на несколько
  сообщений (лимит 4096).
- **Сообщение не теряется**: если Telegram отклонит разметку, отправка
  повторяется простым текстом.
- **Уведомления о ходе**: завершён, ошибка, блокировка, лимит токенов, отмена —
  с рабочим каталогом, названием сессии, вашим запросом и ответом агента.
- **План на утверждение** приходит вместе с текстом плана.
- **Ответы на вопросы**: кнопки по вариантам; свободный ответ — обычным
  сообщением.
- **Подтверждения инструментов**: «✅ Allow once» / «❌ Reject».
- **Без дублей**: при включённых ответах вместо отдельного уведомления приходит
  сразу сообщение с кнопками.
- **Работает вместе с Web UI**: Telegram и браузер соревнуются за один вопрос,
  побеждает первый ответ, второй промпт снимается.

## Установка

```bash
dsh plugin --profile web add dsh-telegram-plus
# или напрямую из репозитория
dsh plugin --profile web add github:5alex52/dsh-telegram-plus
```

Для десктопа — `--profile desktop`. Пакет объявляет `dsh.bundle`, поэтому
`dsh plugin add` сам монтирует строку `telegram-plus`. Перезапустите `dsh` и
откройте **Настройки → Telegram**: вставьте токен бота (**Save token**), укажите
chat id, включите тумблеры.

Токен создаётся у [@BotFather](https://t.me/BotFather), свой числовой id можно
узнать у [@userinfobot](https://t.me/userinfobot). Для ответов нужен **личный**
чат (положительный числовой id): в группе нельзя проверить, кто нажал кнопку,
поэтому группы и каналы получают только уведомления.

## Настройки

| Ключ | По умолчанию | Значение |
| --- | --- | --- |
| `chatId` | `""` (выключено) | Куда отправлять. Ответы — только положительный числовой id. |
| `tokenRef` | `TELEGRAM_BOT_TOKEN` | Ссылка на токен в хранилище credentials. |
| `format` | `html` | `html` рендерит Markdown, `plain` отправляет как есть. |
| `allowReplies` | `true` | Читать нажатия кнопок и ответы из чата. |
| `answerTimeoutMinutes` | `0` | Закрыть промпт через N минут; `0` — ждать. |
| `silent` | `false` | Без звука уведомления. |
| `notifyTurnComplete` / `notifyTurnError` / `notifyTurnAborted` | `true` / `true` / `false` | Уведомления о ходе. |
| `notifyQuestions` / `notifyPlanReviews` / `notifyApprovals` | `true` | Вопросы, планы, подтверждения. |

Те же ключи можно задать в `cordis.patch.yml` профиля:

```yaml
- id: telegram-plus
  name: dsh-telegram-plus
  config:
    chatId: "123456789"
    tokenRef: TELEGRAM_BOT_TOKEN
    format: html
    allowReplies: true
```

## Как работает ответ

Плагин встаёт в waterfall `user-questions/request` и `approval/request` с
`prepend: true` и вызывает `next()`, поэтому браузерный ответчик тоже получает
запрос. Дальше два промпта соревнуются: побеждает первый ответ, второй
отменяется через общий abort-signal. Если клиент браузера не подключён, цепочка
UI отвечает `unavailable` для подтверждений — плагин продолжает ждать Telegram,
а не закрывает запрос отказом.

Текст сообщением **не** подтверждает инструмент: только кнопка. Для нескольких
вопросов сразу отвечайте одной строкой на вопрос, по порядку.

## Безопасность

- Отвечать может только настроенный личный чат: каждый апдейт проверяется по
  `chatId` до любых действий.
- Нажатое «Allow once» — это реальное разрешение. Держите бота в личном чате, а
  токен — в хранилище credentials, не в общем YAML.
- Бот не управляет агентами и не даёт доступ к сессиям — только присылает и
  принимает ответы.
- Бэклог Telegram при старте пропускается: старое сообщение не ответит на новый
  вопрос.

## Ограничения

- Один поллер на бота: вторая интеграция с тем же токеном получит `409
  Conflict`, плагин предупредит в лог и продолжит попытки.
- Группы и каналы — только уведомления.
